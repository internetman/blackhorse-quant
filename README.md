# 黑马量化：M2 首页与 R02 板块雷达

生产网站现在采用两层入口：

- `/`：Mark Minervini 2 个股趋势看板，作为首页；
- `/m2-table`：最近一次 i 问财导入快照的关键字段表格，并提供均线距离、阶段推演和建议分层图形；
- `/radar`：原有 R02 盘面板块雷达，作为首页的跳转页（源码文件为 `radar.html`）。

M2 看板负责主动查看阶段、筑底足迹、Pivot、日K证据和规则化购买建议；R02 雷达负责板块温度、趋势和宽度校验。两套页面共用同一个部署，但不混淆各自的交易口径。

本地 / Vercel 可部署的网页仪表盘，用于同时观察：

- 盘面总览：上证指数、创业板指、科创50、纳斯达克、恒生指数。
- 全市场温度：涨跌幅中位数、上涨占比、P25/P75。
- 实时板块指数：东方财富行业板块指数按当日涨跌幅排序。
- Top 5 板块趋势：前 5 名板块最近 10 个交易日相对首日收盘的涨跌幅趋势。
- 板块归因分析：按上涨家数、龙头强度、10 日相对趋势、成交额拆解上涨来源。
- 板块领涨股：每个 Top 5 板块内按当日涨跌幅列出前 10 只股票。
- R02 宽度校验：独立计算的全市场及行业 MA20/MA50 宽度，用于观察参与程度和主线资格。

## 市场天气（2026-11-04）

入口 `/radar#market-breadth`。沿用现有全市场快照，独立计算，不依赖大盘云图；绝不使用 M2 候选池代替全市场。

- 全市场等权 MA20/MA50 站上比例、5 个交易日变化、涨跌家数、涨跌幅中位数、行业扩散比例；每个比例保留分子和分母。
- 指数确认：上证、沪深300、中证1000、创业板、科创50的同日收盘及 MA50；至少 3/5 个指数站上 MA50 且 MA50 近20日上行才算指数确认。指数缺失不算通过。
- 天气是透明、未回测的观察分类，不是 Minervini 原著参数，也不直接修改正式 R02 或账户仓位：MA20<30% 或 MA50<30% 为偏弱；低位最近5日改善为修复；MA20/MA50均≥50%、行业半数以上站上比例≥50%、MA20五日不下降，为扩散；上述扩散连续3日、MA20≥60%、MA50≥55%，再结合指数确认及至少一个 R02 行业通过，才标为顺风。其它组合为分化。
- 仓位提示引用现行 R05：偏弱/修复仅参考20%～30%防守档；分化/扩散参考40%～50%；顺风参考60%。它们是环境参考上限，不是目标仓位或加仓指令；还须满足个股买点、账户风险、行业集中度和已有仓位限制。数据不足/过期直接暂停加仓判断。
- 收盘计算以 Asia/Shanghai 为准，16:00前只计算前一日及更早的完整日K；使用实际指数交易日校验，节假日不伪造交易日。数据超过预期交易日或历史覆盖不足95%不能放行。
- `market-breadth-status.json` 记录最近采集尝试和失败，不覆盖最后成功快照；网页展示采集时间、实际收盘日、覆盖率和滞后状态。没有定时任务成功记录时不声称自动更新正常。
- 手动运行 `python3 market_breadth.py --workers 16`；失败返回非零状态，保留旧快照。`--output` 可生成待核验快照。发布只同步本次相关文件，保留线上其它页面。
- 2026-11-04排查：当前本机自动任务列表没有“R02 每日板块雷达”，仅存“R02 周度主线重排”，因此旧文档提及的工作日16:10自动更新不能视为正在运行。本次全量重抓遇到超过5%历史失败，保留旧快照并显示失败，尚未恢复有效的每日全量更新。

## 本地运行

```bash
python3 server.py
```

然后打开：

```text
http://127.0.0.1:8765/
```

原 R02 板块雷达在：

```text
http://127.0.0.1:8765/radar
```

也可以指定端口：

```bash
R02_DASHBOARD_PORT=8766 python3 server.py
```

## Vercel 部署

当前结构支持直接部署到 Vercel：

```text
index.html          # M2 首页
radar.html          # 原 R02 板块雷达源码，对外路径为 /radar
m2-styles.css       # M2 首页样式
m2-data.js          # M2 当前观察快照
m2-archive.js       # 首页与表格页共用的人工归档存储
m2-app.js           # M2 首页渲染逻辑与动态 VCP 图
m2-assets/          # 历史截图存档，不作为实时图形来源
m2-table.html       # i问财导入表格页
m2-table-data.js    # 由导入 xlsx 提取的表格快照
m2-table-app.js     # 表格筛选、排序、推演摘要与图形
m2-table.css        # 表格页与推演图形样式
m2-snapshot.json    # 本地 Session 生成的 M2 选股日K与 VCP 快照
server.py           # 本地服务 + 共享数据抓取逻辑
api/dashboard.py    # Vercel Python Serverless Function
api/m2-watchlist.py # M2 已发布报价接口；dynamic=1 时才抓实时行情
api/m2-history.py   # M2 已发布快照接口；dynamic=1 时才动态抓取日K
vercel.json         # Other 框架、空构建命令、根目录静态输出、API 路由
```

Vercel 上的访问路径：

- `/`：静态页面
- `/radar`：原 R02 板块雷达
- `/m2-table`：M2 待观察股票池
- `/api/dashboard`：实时数据 JSON
- `/api/m2-watchlist`：默认返回已发布收盘报价；`?dynamic=1` 才抓实时价格与日涨跌 JSON
- `/api/m2-history`：默认返回已发布的 `m2-snapshot.json`；`?dynamic=1` 才动态抓取复权日K
- `/m2-snapshot.json`：网页正常读取的本地 Session 快照；打开网页不再等待逐只历史行情请求

M2 的 `m2-data.js` 保存候选池摘要；`m2-table-data.js` 只展示 MA200 近 20 日斜率至少 `0.20%` 且不属于 `S2转弱` 的股票。被移出的股票仍保留在 `m2-stage-state.json` 历史状态档案中，以便转强后自动重新入池。`m2-snapshot.json` 由本地 Session 在收盘后统一抓取报价、日K、均线和 VCP 初筛结果，网页只负责读取和展示。快照超过 36 小时或只完成部分股票时会标记为“已过期 / 部分沿用”，不会把旧数据伪装成当天全量数据。
首页卡片和表格行都支持人工归档。归档记录由 `m2-archive.js` 按股票代码写入当前域名的浏览器 `localStorage`，刷新页面、重新部署和下一次收盘数据更新后仍会保持；首页与 `/m2-table` 共用归档箱并可恢复。人工归档只改变当前浏览器的候选视图，不删除行情、历史 K 线或阶段档案，也不会同步到其它浏览器或其它域名。
候选池的 Pivot 选择依据、阶段证据、收缩次数、底部时间、修正深度和量能条件必须分栏显示；收缩次数、底部时间和修正深度没有历史 OHLCV 扫描确认时必须保留“未确认 / 未接入历史统计”，不能写成确定买点。

部署步骤：

1. 在本目录初始化独立 Git 仓库并提交文件。
2. 在 GitHub 创建一个新仓库，把本目录推送上去。
3. 在 Vercel 新建 Project，导入该 GitHub 仓库。
4. Framework Preset 选择 `Other`；不需要 Build Command。
5. 部署完成后打开 Vercel URL。

本项目没有 npm / pip 依赖，当前只使用 Python 标准库。
Vercel 函数会并发拉取同一批公开数据源，并使用较短上游超时；单个数据源失败时页面保留其它模块并在 warning 中显示原因。
10 日趋势图按 30 分钟缓存处理：新 K 线拉取成功才更新缓存；拉取失败时沿用上一次成功的同板块趋势，并在页面上标注“沿用上次趋势”。浏览器本地也会保留一份趋势缓存，用于 Vercel 冷启动或上游临时失败时兜底。
M2 选股快照建议在 A 股收盘后 15:30–16:00 生成一次，次日盘前或盘中只读展示；网页每 30 分钟检查一次是否已经上传了新快照。快照脚本会按当前 `m2-table-data.js` 的观察池股票加核心档案抓取历史 OHLCV，避免观察记录没有 K 线；若公开行情源临时失败，脚本只写带 `partial` 状态的可用结果，或沿用已有快照，不清空已可用日 K。R02 雷达页面仍按原逻辑自动刷新 30 分钟；手动按钮会重新读取网页资源。Hermes 或本地 Session 可在收盘后执行 `bash handoff/website-sync/refresh-m2-site.sh`，一次完成抓取、分析和推送。M2 建议只做观察分层：`待观察`、`过热不追，保留观察`、`待复核观察`；它不执行交易，最终买不买由使用者决定。
板块排行按最近 24 小时的成功快照兜底：新快照拉取成功才覆盖；若东方财富板块排行接口临时失败，则沿用上一次成功排行并标注“沿用上次排行”。盘前若没有可用快照，或快照全部为 0、成交额为空、涨跌家数为 0/0，会被标记为“板块排行未就绪”，前端不渲染假 Top5 / 前15 排行，并显示具体原因。旧快照只用于断线展示，不改变正式 R02 宽度结论。

## 口径

- 实时板块排行：东方财富 `push2` / `push2delay` 行业板块，`fs=m:90+t:2`，按 `f3` 当日涨跌幅排序。
- 10 日趋势：东方财富 `push2his` / `push2delay` 板块日 K，`secid=90.BKxxxx`，前端按首日收盘归一化为相对涨跌幅。
- 领涨 10 股：东方财富 `push2` / `push2delay` 板块成分股，`fs=b:BKxxxx`，按 `f3` 当日涨跌幅排序。
- 盘面指数：东方财富 `push2` / `push2delay` 指数行情。
- 全市场收盘涨跌分布与 MA20/MA50 宽度：`market_breadth.py` 从东方财富沪深京 A 股名单和前复权日 K 独立计算，腾讯前复权日 K 作为备用，保存在 `market-breadth.json`。`providerCounts` 记录各来源样本数量。
- 行业热力图为当前东方财富行业分类回溯，个股等权；含 ST 和北交所。剔除当日无成交、历史不足样本，每格保留分子与分母，不与旧大盘云图行业序列拼接。
- 同日历史覆盖低于 95% 时计算失败并保留旧文件；网页标明收盘日期，首次 API 失败仍可独立读取宽度快照，浏览器也保留最近一次成功快照。
- 收盘更新由既有 Codex 自动任务“R02 每日板块雷达”执行，保留工作日北京时间 16:10 的计划并加入采集、校验和网站部署；依赖本机在线与 Codex 可运行。节假日沿用最近收盘，失败不覆盖旧结果。现有 GitHub 凭据不具备 workflow 权限，未启用 GitHub Actions。
- 手动更新：`python3 market_breadth.py`，随后执行现有部署脚本。生产宽度快照比本地新时，部署脚本优先保留较新的结果。
- M2 候选股行情：东方财富 `push2` / `push2delay` `ulist.np`。
- M2 候选股动态日K：东方财富 `push2his` / `push2delay` `stock/kline/get`，前复权日线。

## 交易系统边界

- 实时板块涨跌是盘中温度计。
- R02 宽度是交易系统里的板块资格证。
- 二者必须分层展示，不能互相替代。
- 本工具只做盘面监控、数据展示和规则化购买建议，不执行交易；“均线通过”不等于立即买入，建议仍需结合 Pivot、收缩、突破量和止损计划复核。
- 动态 VCP 图只绘制价格、成交量、MA50/150/200、候选 Pivot 和算法初筛的收缩区；收缩区是辅助观察，不等同于人工确认的 VCP 买点。
- 正式交易分析必须回到 Vault 里的 R02 / R04 / R05 / R13 / R15 和账户状态完成预检。
- 若盘中出现强势集群，`R02_CURRENT` 可以临时标记为“盘中临时 R02”；正式周度 R02 仍须等收盘后行业宽度确认。
- 每日收盘后必须用雷达复算 R02，并同步 `server.py` 里的 `R02_CURRENT`；如果主线不变，也要更新日期，避免面板停留在旧交易日。

## 注意事项

- 部署到 Vercel 后，页面会成为公网可访问页面；不要放入账号、持仓截图、API key 或任何私密数据。
- 东方财富和大盘云图接口是公开前端数据源，可能因为网络、限流、字段变化或跨境访问失败而返回空数据。
- Vercel 出口访问东方财富偶尔会遇到 502 / 断连；页面必须优先保留上一次成功快照，并清楚标注快照时间。
- `R02_CURRENT` 是 `server.py` 中的面板 R02 摘要；若只是盘中临时更新，必须在 note 中保留正式 R02 口径与待收盘确认边界。
